1. 분석 개요

1.1 분석 목적 및 범위

Syncro는 서울시 교통 상황의 실시간 모니터링을 위해 국토교통부 V2X 신호 API, 서울시 TOPIS 도로 속도 API, 기상청 초단기실황 API, 행정안전부 도로 위험지수 API의 4종 공공데이터를 수집·통합한다. 본 문서는 각 API의 데이터 명세, 수집 방식, 전처리 로직, 활용 방법을 분석하며, AI 에이전트가 교통 상황을 자연어로 해석하기 위해 필요한 교통·기상 도메인 지식을 함께 기술한다.

분석 범위: ① 교통 신호·속도 데이터 ② 기상 조건 데이터 ③ 도로 위험도(돌발상황 지수) 데이터 ④ 데이터 통합 처리 및 품질 관리

2. 교통 신호 데이터 (V2X)

2.1 데이터 구조

응답 1건은 교차로 1개의 평탄(flat) 필드 집합이며, 필드명은 방향 접두사와 신호유형의 조합으로 구성된다. 시스템은 이를 방향 → 신호유형의 2단 계층 구조로 변환한다.

구분값
방향 코드 8종nt(북) · et(동) · st(남) · wt(서) · ne(북동) · se(남동) · sw(남서) · nw(북서)
신호유형 6종Stsg(직진) · Ltsg(좌회전) · Pdsg(보행) · Utsg(유턴) · Bssg(버스) · Bcsg(자전거)
필드 조합 예ntStsgSttsNm(북 직진 상태), ntStsgRmndCs(북 직진 잔여시간)

2.2 신호 상태 값

상태 값의미
stop-And-Remain적색 — 정지 유지
protected-Movement-Allowed녹색 — 보호 이동 허용
permissive-Movement-Allowed비보호 이동 허용

2.3 잔여시간(rmndCs) 해석 — 핵심 유의사항

  • 단위는 1/10초(데시초)다. 값 300 = 30초. 시스템은 AI 전달·화면 표시 전에 10으로 나눈다.
  • 36000 이상은 센티넬 값(잔여시간 불명)으로, 해당 신호 데이터를 폐기한다.
  • rmndCs는 수집 시점의 스냅샷 잔여시간이며 신호 사이클 전체 길이가 아니다. AI 도구 설명에 이 한계를 명시하여 과잉 추론을 차단한다.
  • 화면의 초단위 카운트다운은 30초 폴링 사이를 클라이언트 0.1초 타이머로 보간한 값이다(잔여시간 − 경과시간, 0 미만 클램프).

2.4 신호 해석 규칙 (AI 권고 근거)

관측 패턴해석 및 권고 방향
적색 + 잔여시간 높음해당 방향 대기 과다 — 적색 단축 또는 대향 녹색 단축으로 순서 앞당김 권고
녹색 + 잔여시간 낮음곧 적색 전환 — 혼잡 시 녹색 연장 검토
속도 낮음 + 특정 방향 적색 장기해당 진입 방향이 혼잡 원인일 가능성 — 방향별 속도와 교차 검증

3. 도로 속도 데이터 (TOPIS)

3.1 수집·매핑 구조

  • 속도는 도로 링크(linkId) 단위로 제공된다. 교차로와 직접 연결되지 않으므로 매핑 테이블을 생성한다.
  • 대표 링크 매핑: 교차로 최근접 링크(거리 상한 내). 방향별 매핑: 진입 링크의 접근 방위각을 V2X 8방향 코드에 스냅(허용 오차 67.5도).
  • 갱신은 60초 주기, 회당 최대 80링크를 라운드로빈으로 순환(전체 링크가 80개를 초과할 때 호출량 보호).

3.2 대표 속도 산출 규칙

규칙. 교차로 대표 속도(speedKph)는 방향별 진입 속도가 존재하면 그 중 최저값(가장 막힌 진입)으로 한다. 교차로 혼잡은 평균이 아니라 최악 진입로가 결정하기 때문이며, 방향별 원본 값도 함께 제공하여 세부 분석을 지원한다.

4. 기상 데이터 (기상청 초단기실황)

4.1 좌표 변환과 기준시각

  • 요청 좌표는 위경도가 아닌 기상청 격자(nx, ny)다. Lambert Conformal Conic 투영(표준위도 30°/60°, 기준 126°E/38°N, 격자 5km)으로 변환한다.
  • 기준시각 규칙: 현재 분이 45분 미만이면 한 시간 전 정시를 base_time으로 사용한다. 초단기실황이 매시 40분경 생성되므로 직전 정시 데이터가 아직 없을 수 있기 때문이다.

4.2 활용 항목

5. 도로 위험도 데이터 (돌발상황 지수)

5.1 등급 체계

코드등급해석
01안전통상 운영
02주의모니터링 강화
03위험관제 주의·우회 검토
04심각우선 대응 대상

5.2 수집 정책

  • 5분 주기. 회당 최대 250건, 동시성 2, 동일 링크 최소 재요청 간격 5분.
  • 이전 실행 진행 중 새 구역 요청이 오면 보류 플래그를 세우고, 현재 실행 종료 직후 즉시 재실행한다.
  • 연속 실패가 임계치를 넘으면 해당 회차를 중단한다(외부 API 보호).

7. 데이터 통합·품질 관리

7.1 통합 원칙

  • 화면과 AI가 동일한 통합 객체(TrafficStatus)를 본다 — 단일 합산 지점(enrichTrafficStatus)에서만 병합한다.
  • 식별자 체계가 다른 데이터(경찰청 신호 ↔ V2X)는 좌표 기반 350m 최근접 매칭으로 결합하고 매칭 거리를 함께 기록한다.

7.2 품질 관리 규칙

상황처리
V2X 빈 응답캐시를 비우지 않고 유지, 다음 주기 재시도. 구역 전환 시 3회 재시도
보조 API 실패기존 값 유지 + stale 플래그 — 더미·랜덤 값을 생성하지 않는다
잔여시간 센티넬(≥36000)해당 신호 폐기
