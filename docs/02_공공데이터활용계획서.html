2. 데이터별 활용 계획

2.1 V2X 교차로 신호정보 (실시간)

엔드포인트apis.data.go.kr/B551982/rti/tl_drct_info (서울: stdgCd=1100000000, JSON)
수집 방식30초 주기 스케줄러. 페이지네이션 순회, 대상 교차로 전부 확보 시 조기 종료
전처리방향 8종 × 신호유형 6종 필드명 동적 조합 파싱(ntStsgSttsNm 등) → 계층 구조화. 잔여시간(rmndCs)은 1/10초 단위이며 36000 이상은 센티넬로 폐기
활용신호 패널 표시, 평균 대기시간 계산, AI 챗봇 신호 분석(적색+잔여 높음 → 단축 권고 등)
장애 대응빈 응답 시 캐시 유지. 구역 전환 시 1초 간격 3회 재시도

2.2 V2X 교차로 위치정보 (마스터)

엔드포인트apis.data.go.kr/B551982/rti/crsrd_map_info
수집 방식서버 최초 기동 시 1회 전수 적재(이미 적재되어 있으면 스킵). 500건 배치 저장
활용교차로 마스터 테이블(CROSSROAD). 구 선택 시 Haversine 반경 검색의 기준 데이터

2.3 경찰청 교차로 신호현시 정보 3종

엔드포인트 교차로 목록 CrossRoadInfoService/getCrossRoadInfoList
현시구성 CrossRoadInfoService/getCrossRoadInfoDetail
운영계획 PlanCrossRoadInfoService/getPlanCROPInfo (지역코드 L01=서울)
수집 방식서버 최초 기동 시 1회 적재
전처리좌표는 1e7 스케일 정수 문자열 → 실수 복원. A/B링 1~8 컬럼을 현시 배열로 해석
활용시뮬레이션 페이지의 현시 재현(현재 시각 기준 활성 운영계획 선정 → 사이클 내 경과 시간 → 활성 현시 계산), Webster 최적화의 입력(주기·현시 초)
비고V2X 교차로 ID와 체계가 달라 직접 조인 불가 → 좌표 기반 350m 최근접 매칭으로 실시간 속도를 결합

2.4 TOPIS 도로 소통정보 (구간 속도)

수집 방식60초 주기. 현재 구역에 매핑된 링크만 대상으로 하되, 회당 최대 80링크를 라운드로빈 로테이션으로 순환 갱신. 동시성 상한 4, 회당 시간 예산 12초
전처리교차로별 대표 속도는 방향별 진입 속도 중 최저값(가장 막힌 진입) 채택. 방향별 속도는 V2X 방향 코드(nt/et/...)에 스냅
활용혼잡도 판정(15/25km/h 기준), 병목 식별, 시뮬레이션 경로 구간 속도, Webster ΣY 추정 입력
장애 대응실패 시 기존 값 유지 + stale 플래그. 이전 실행 미완료 시 중복 실행 차단

2.5 TOPIS 도로망 마스터 (축·링크·버텍스)

수집 방식관리자 수동 동기화 API(/api/signal/topis/master/sync)로 도로구분 → 도로축 → 축링크 → 링크버텍스를 순차 적재. 버텍스는 병렬 수집 후 동기화 리스트로 합산
활용시뮬레이션 경로의 구간-링크 매칭(거리·방위각 차이 제한), 도로망 형상 표시, 차량 이동 애니메이션 좌표
비고마스터는 TTL 메모리 캐시로 보관. 링크 버텍스는 사전 구축 파일 우선 사용 옵션 지원

2.6 기상청 초단기실황

엔드포인트apis.data.go.kr/1360000/VilageFcstInfoService_2.0/getUltraSrtNcst
수집 방식10분 주기. 위경도를 기상청 격자(nx, ny)로 변환(Lambert Conformal Conic 투영) 후 호출
기준시각 규칙현재 분이 45분 미만이면 한 시간 전 정시를 base_time으로 사용 — 초단기실황이 매시 40분경 생성되어 직전 정시 데이터가 아직 없을 수 있기 때문
전처리카테고리 코드 매핑: T1H(기온) · RN1(1시간 강수량) · REH(습도) · WSD(풍속)
활용대시보드 날씨, AI 분석 컨텍스트(전 교차로 공유 스냅샷), 민원 화면·로그인 브리핑 날씨

2.7 도로 위험지수 정보

엔드포인트apis.data.go.kr/B552061/roadDgdgrLink/getRestRoadDgdgrLink
수집 방식5분 주기. 회당 최대 250건, 동시성 상한 2, 5분 미만 경과 데이터는 재요청 금지. 이전 실행 중 구역이 바뀌면 완료 직후 즉시 재실행(pending 플래그)
전처리위험등급 코드 → 한글 매핑(01 안전 / 02 주의 / 03 위험 / 04 심각)
활용교차로 위험등급·지수 표시, AI 분석 컨텍스트, 위험 순위 목록

2.8 UTIC CCTV 정보

수집 방식서울 CCTV 메타 엑셀을 최초 기동 시 파싱 적재 후, UTIC API로 스트림 ID·채널을 매핑
활용지도 CCTV 마커, CCTV 관제 페이지. 영상은 UTIC 공개 스트림 페이지 임베드 방식

2.9 네이버 뉴스 검색 API (민간)

수집 방식요청 시(관리 트리거) 4개 섹터 검색어로 최신 100건씩 수집. 본문은 비동기 병렬 수집(동시 20)
전처리·분석키워드 관련도 검증 → BERT 기사 유형 분류 → TF-IDF+로지스틱 낚시성 확률 → 요약·감성(혼잡악화/교통개선/중립). 링크를 PK로 중복 제거
활용뉴스 대시보드(카테고리·감성 필터, 낚시성 점수 표시)

4. 인증키 관리 및 준수사항

  • 공공데이터포털 서비스키는 application-secret.properties(버전관리 제외)로 분리 보관한다.
  • DB 접속은 Oracle Wallet(mTLS) 인증을 사용한다.
  • 각 API의 트래픽 정책(일일 호출 한도)을 초과하지 않도록 주기·상한을 설정값으로 관리한다.
  • 수집 데이터는 통계·관제 목적으로만 사용하며 원문 출처(기관)를 본 문서에 명시한다.
  • 일부 보조 키(메일·RAG)가 코드에 잔존하는 한계가 있으며 환경변수 이관을 계획한다(요구사항정의서 5.2).
