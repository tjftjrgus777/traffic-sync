1. 개요

1.1 목적

Syncro는 서울시 교차로의 V2X 신호 데이터를 실시간 수집하고, 로컬 LLM 기반 AI 에이전트가 교통 상황을 분석·권고하는 관제 의사결정 지원 시스템이다. 본 문서는 시스템이 충족해야 하는 요구사항을 식별·정의하고 구현 현황을 추적한다.

1.2 범위

  • 실시간 교통 데이터 수집·통합(신호·속도·기상·위험도)과 대시보드 시각화
  • AI 챗봇(ReAct)·멀티에이전트 분석·신호 시뮬레이션(Webster 공식) 등 분석 기능
  • 교통량 예측, 교통 뉴스 분석, 시민 민원 접수·분류 등 부가 서비스
  • 실제 신호제어기 연동(신호 변경 집행)은 범위에 포함하지 않는다 — 5.1 참조

NFR-01보안(AI)AI 분석은 외부 API 없이 로컬 LLM으로 수행한다. 관제 데이터가 외부로 전송되지 않는다(민원 사진·뉴스 등 공개 서비스 영역 제외)
NFR-02가용성외부 API 장애 시 캐시 유지·stale 플래그·재시도(구역 수집 3회)로 동작을 지속한다. 더미·랜덤 데이터를 생성하지 않는다
NFR-03가용성의존 서버(Spring·AnythingLLM) 다운 시 AI 에이전트는 오류 메시지를 반환하되 프로세스는 유지된다
NFR-04성능외부 API 호출은 동시성 상한(TOPIS 4, 위험도 2)과 회당 처리량 상한(속도 80링크 로테이션, 위험도 250건)을 지킨다
NFR-05성능AI 응답은 SSE로 중간 과정을 즉시 표시하고, 프론트는 120초 타임아웃 후 최대 2회 자동 재시도한다
NFR-06동시성공유 캐시 갱신은 원자적 참조 교체로, 구역 전환·폴링 경합은 CAS 가드로 보호한다
NFR-07데이터DB 인증은 Oracle Wallet(mTLS)을 사용하고 핵심 API 키는 비공개 설정 파일로 분리한다
NFR-08운영전체 서버는 단일 스크립트(start-all.sh)로 기동하며 워커 모델은 기동 시 프리로드한다

5. 제약사항 및 한계

5.1 범위 외 항목

  • 실제 신호 제어 — 신호제어기 권한은 경찰청 소관이다. 본 시스템은 권고·시뮬레이션까지만 수행하며, 제어 API를 의도적으로 미구현 상태로 두어 관제사 승인 절차를 강제한다.
  • 간선 연동(공통 주기) 최적화 — 현재는 교차로별 독립 최적화이며 축 단위 연동은 향후 과제다.
