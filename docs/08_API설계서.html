1. 공통 사항

항목내용
기본 URLSpring http://localhost:8080 · 에이전트 http://localhost:8001 · 예측 :5002 · 민원 분류 :8002 · 뉴스 :5001
데이터 형식JSON(UTF-8). 민원 접수·사진 분류는 multipart/form-data
스트리밍SSE(text/event-stream) — data: {JSON} 라인 형식, 종료 이벤트 {"type":"done"}
CORS개발 오리진(localhost:5173 계열) 허용
인증세션·토큰 미사용(PoC). 사용자 식별은 요청 본문 userId/userEmail로 수행 — 한계로 명시

2. Spring Boot API (:8080)

2.1 실시간 교통·지도

방식경로설명
GET/api/signals현재 캐시의 전체 교차로 통합 상태 목록(보조 데이터 병합 포함)
POST/api/fetch-area구역 수집 전환. 쿼리: guName, lat, lon, radius(기본 1.0, 프론트 2.5 사용). 동시 요청 시 409
GET/api/crossroads/nearby좌표 반경 내 교차로 목록(순수 DB 조회, 멀티에이전트용). 쿼리: lat, lon, radius
GET/api/context/{crsrdId}교차로 1건 통합 상태(AI 도구·디버깅용)
POST/api/district/report구 단위 AI 리포트(에이전트 프록시). 본문: {district}
POST/api/admin/sync-topisTOPIS 도로망 마스터 동기화(관리)

2.2 신호계획·시뮬레이션

방식경로설명
GET/api/signal/crossroads신호 교차로 전체 목록(시뮬레이션 지도 핀)
GET/api/signal/crossroads/{intNo}현시구성·운영계획 원본 조회
GET/api/signal/simulation/context/{intNo}시뮬레이션 컨텍스트 — 주기, 활성 현시, 현시별 초·방향, 인근 실시간 속도(350m 좌표 매칭)
POST/api/signal/simulation/route-traffic경로 노드 배열 → 구간별 링크 매칭·상하행 속도·병목 판정·차량 이동 데이터
GET/api/signal/simulation/managed-traffic-links관리 대상 도로 링크(형상 포함) — 중심·반경 선택
POST/api/signal/simulation/managed-traffic-link-status지정 링크들의 현재 속도 상태
POST/api/signal/topis/master/sync · GET /status도로망 마스터 동기화·상태 확인

2.3 AI 챗 프록시

방식경로설명
POST/api/chat지도 챗봇 단건. 본문: {crsrdId?, question, userEmail?} → {answer}
POST/api/simulation-chat시뮬레이션 분석. 본문: {intNo?, question, simulation?, routeTraffic?, bottleneckIntNos?, contexts?, userEmail?} → {answer, adjustments, report}. userEmail 존재 시 보고서 메일 자동 발송
POST/api/simulation-chat/stream위 기능의 SSE 버전(신호계획 조회 단계 이벤트 후 에이전트 스트림 프록시)
POST/api/bottleneck-email구 병목 리포트 생성(에이전트) 후 메일 발송. 본문: {district, userEmail}

2.4 인증·계정

방식경로설명
POST/api/auth/login로그인. CIVIL·PENDING·REJECTED 차단 분기 포함. 응답에 isTempPw 포함
POST/api/auth/register관제사 가입(PENDING 생성)
GET/api/auth/find-id이름·전화로 아이디 조회(뒤 3자리 마스킹)
POST/api/auth/find-pw임시 비밀번호 발급·메일 발송
GET/api/auth/admin/users관리자: 유저 목록
POST/api/auth/admin/approve/{userId} · /reject/{userId}관리자: 승인·거절
POST/api/auth/alert경보 메일 수신 토글 {userId, alertEmail}
POST/api/auth/change-pw비밀번호 변경(임시 플래그 해제)
GET/api/auth/alert-emails수신 동의+승인 유저 이메일 목록
POST/api/civil/auth/login · /register민원 시민 로그인·가입(즉시 승인, ROLE=CIVIL)
GET/api/civil/auth/weather좌표 기반 현재 날씨(민원·브리핑용). 쿼리: lat, lng

2.5 민원

방식경로설명
GET/api/complaints민원 목록(쿼리 guName 선택)
POST/api/complaints민원 접수(multipart: userId, userName, title, category, content, lat, lng, address, department?, aiReason?, photos[]?)
PATCH/api/complaints/{id}/status상태 변경(접수/처리중/완료) — 신고자 메일 자동 발송
DELETE/api/complaints/{id}민원·사진 일괄 삭제
GET/api/complaints/photos/{photoId}사진 BLOB 바이트 반환(Content-Type 보존)

2.6 기타 (예측·뉴스·CCTV·메일)

방식경로설명
GET/api/stations교통량 지점 목록
GET/api/forecast/station/{stationId}지점 24시간 예측(내부에서 예측 서버 호출) → {stationId, stationName, up[24], down[24]}
GET/api/news/latest뉴스 목록. 쿼리: limit(기본 200), category?
GET/api/cctv · /api/cctv/areaCCTV 전체/반경 목록(streamId·채널 포함)
POST/api/email/send메일 발송 단일 창구. 본문: {to, subject, body}

2.7 WebSocket

채널설명
ws://localhost:8080/ws/traffic30초 주기(및 구역 전환 시) 전체 교차로 통합 상태 배열 푸시. 클라이언트는 연결 직후 /api/signals로 초기 적재, 종료 시 3초 후 재연결

3. AI 에이전트 API (:8001)

방식경로설명
GET/health상태 확인(모델·MCP 연결)
POST/api/agent/chat지도 챗봇 단건(ReAct) → {answer}
POST/api/agent/chat/stream지도 챗봇 SSE. 이벤트: action/observation/thought/answer/route_multi/done. 주변 분석 의도 시 route_multi로 멀티에이전트 재라우팅 지시
POST/api/agent/multi-analyze/stream멀티에이전트 SSE. 이벤트: analyze_init → worker_start/done(4기) → discussion_start → round_start(1~3)/discuss_start/done → orchestrator_start/done
POST/api/agent/simulation-chatWebster 최적화. 입력: contexts(신호계획)·routeTraffic·simulation? → {answer(설명), adjustments(코드 계산), report(상세 보고서)}
POST/api/agent/simulation-chat/stream위 기능 토큰 스트리밍(token → done에 answer·adjustments 동봉)
POST/api/agent/district-report · /stream구 단위 리포트(단건/SSE)
POST/api/agent/bottleneck-email · /stream병목 경보 리포트 생성(스트림 버전은 완료 후 Spring 메일 창구로 발송)
POST/api/nav/intent음성 명령 의도 분류 → {action: navigate|select_gu|mypage|logout|unknown, page?/gu?}
POST/api/agent/stop진행 중 LLM 생성 강제 중단(연결 소켓 종료 후 재생성)

4. Flask API

4.1 교통량 예측 (:5002)

방식경로설명
POST/predict_traffic본문: {Station_Number} → 당일 0~23시 상행(direction_0)/하행(direction_1) 예측 배열. 지점 미존재 시 404

4.2 민원 분류 (:8002)

방식경로설명
POST/api/civil/classifymultipart: title, image → {category(15종), department, reason, convertedImage?(HEIC→JPEG 변환본)}. 모델 과부하 시 4단 폴백
GET/health · /models상태·사용 가능 모델 확인

4.3 뉴스 분석 (:5001)

방식경로설명
POST/news/fetch수집·분석 파이프라인 백그라운드 실행. 중복 실행 시 409 {status:"already_running"}
GET/news/latestDB 직접 조회(쿼리: limit, category?)
GET/health상태·모델 로드 여부

5.2 시뮬레이션 최적화 (POST /api/simulation-chat)

요청
{
  "question": "각 병목 교차로의 신호계획을 분석해서 15km/h 이하 구간 전체의 신호를 최적화해줘. ...",
  "bottleneckIntNos": ["2904"],
  "contexts": [{ "intNo": "2904", "intNm": "교차로명", "cycleVal": 140,
                 "phases": [{ "no": 1, "sec": 38, "dirs": ["남북 직진"] }, ...] }],
  "routeTraffic": [{ "fromIntNo": "2901", "toIntNo": "2904", "speedKph": 11.2, "congestion": "정체" }],
  "userEmail": "user@example.com"
}
응답
{
  "answer": "교차로별 변경 요지(LLM 설명문)",
  "adjustments": [{ "intNo": "2904", "phases": [{ "no": 1, "sec": 41 }, ...] }],
  "report": "[Webster 신호 최적화 리포트] ... (코드 생성 상세 계산 과정)"
}

5.3 챗봇 SSE 이벤트 (POST /api/agent/chat/stream)

data: {"type":"action","tool":"get_district_traffic","label":"자치구 교통 현황 조회","args":"district_name=강남구"}
data: {"type":"observation","content":"{ district, total_crossroads, bottleneck_under_15, weather }"}
data: {"type":"answer","content":"강남구 수집 교차로 41개, 평균 21.3km/h ..."}
data: {"type":"done"}
주. 오류 응답은 각 서버에서 {message} 또는 {success:false, error}를 사용하며, 에이전트 SSE는 {"type":"error","content":...} 이벤트 후 done으로 종료한다.
