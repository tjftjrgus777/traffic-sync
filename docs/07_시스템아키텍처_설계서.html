1. 설계 원칙

원칙내용
완전 로컬 AI관제 분석용 LLM 추론은 전량 로컬(Ollama)에서 수행한다. 폐쇄망·망분리 환경을 전제로 외부 API 의존을 제거한다
수치는 코드, 설명은 LLM신호 조정 수치·Webster 계산·상세 보고서는 코드가 산출하고 LLM은 설명만 생성한다(환각 차단)
장애 시 보수적 동작외부 API 실패 시 캐시 유지·stale 표기·재시도. 더미 데이터를 생성하지 않는다
단일 진실 원천화면과 AI가 동일한 통합 캐시(TrafficStatus)를 본다. 메일 발송은 Spring 단일 창구
승인 기반 개입AI 권고는 관제사 승인 후 적용한다. 실신호 제어 API는 의도적 미구현(Human-in-the-loop)

4. 통신 방식 설계

방식사용처선택 사유
REST일반 조회·명령 전반요청-응답형 작업의 표준
WebSocket신호 데이터 브로드캐스트(/ws/traffic)서버 주도 상시 스트림. 30초 주기 전 클라이언트 동시 전파
SSEAI 응답 스트리밍(챗봇·리포트·멀티에이전트)요청당 단방향 스트림. HTTP 그대로 사용, 단계 이벤트 타입화 용이
MCP stdio에이전트 ↔ MCP 도구 프로세스(mcp_server.py)표준 도구 프로토콜. 도구는 별도 포트 없이 에이전트가 서브프로세스로 기동하며 stdin/stdout(JSON-RPC)으로 통신 — 도구 로직을 에이전트 코드와 분리해 결합도 제거
SMTP메일 발송(Gmail SSL 465)모든 발송을 Spring 단일 창구로 일원화
주. 프론트의 SSE 수신은 EventSource가 아닌 fetch 스트림 수동 파싱이다 — EventSource가 GET 전용이라 질문·좌표 등 본문 전송이 불가하기 때문이며, AbortController로 타임아웃(120초)·중단을 통합 처리한다.

5. 동시성 설계

지점기법 및 사유
신호 캐시 전체 갱신새 ConcurrentHashMap 생성 후 volatile 참조 원자 교체 — 갱신 중간 상태(부분 읽기) 노출 차단
구역 전환 ↔ 정기 폴링 경합AtomicBoolean compareAndSet 가드(중복 요청 409) + 폴링 측 진행 여부 확인
WebSocket 세션 목록CopyOnWriteArrayList — 읽기(브로드캐스트) 다수·쓰기(접속/해제) 소수 환경에 적합
TOPIS 속도 갱신중복 실행 차단 + 회당 80링크 라운드로빈 로테이션 + 동시성 4 + 시간 예산 초과분 취소
위험도 갱신동시성 2의 CompletionService, 실행 중 구역 변경 시 보류 후 즉시 재실행(pending 플래그)
멀티에이전트 워커asyncio 병렬 태스크 + 큐 기반 SSE 중계. 연결 종료 시 태스크 일괄 취소
뉴스 파이프라인I/O는 코루틴 세마포어(수집 20·요약 5), CPU(BERT)는 스레드풀(4), DB는 단일 writer 큐 직렬화

6. AI 아키텍처

6.1 LLM 배치

용도모델파라미터비고
ReAct 메인qwen2.5:14btemp 0.3 · 출력 4096 · 컨텍스트 8192도구 호출 안정성 기준 선정
시뮬레이션 설명qwen2.5:14btemp 0.3 · 출력 무제한 · 컨텍스트 16384다중 신호계획+계산 블록 수용
방향별 워커 4기exaone3.5:2.4btemp 0.1 · 출력 6000 · 컨텍스트 8192한국어 경량 모델, 포트별 독립 인스턴스로 실제 병렬
  • Ollama 단일 인스턴스는 요청을 큐잉하므로 워커는 포트(11435~11438)별 독립 프로세스로 기동하고, 기동 스크립트에서 빈 프롬프트로 프리로드한다.
  • 추론 모드: 빠른 응답 경로는 사고 생략(no_think), 정확도 우선 경로는 사고 허용(think). 사고 블록은 사용자 표시에서 분리한다.
  • 생성 중단: 연결 종료 감지(0.3초 폴링) 시 제너레이터 명시 종료로 추론 소켓까지 차단. 별도 정지 API는 공유 클라이언트를 강제 재생성한다.

6.2 MCP 도구 계층

MCP 도구(mcp_server.py)는 에이전트 서버가 기동 시 서브프로세스로 실행하는 별도 프로세스다. 독립 포트 없이 stdin/stdout(JSON-RPC)으로 통신한다. 도구 9종은 Spring REST의 래퍼로, Spring 미가동 시 오류 객체만 반환하여 에이전트 생존을 보장한다. 표준 프로토콜 채택으로 동일 도구 프로세스를 타 MCP 클라이언트에서 재사용할 수 있다.

6.3 RAG (AnythingLLM)

항목설정 · 근거
청크 크기1,000자 — 임베딩 모델 최대 입력 길이(1,000자)에 맞춘 상한이며, 프로젝트 문서의 주제 단위(공식·기준표·절차)가 1,000자 내에 들어와 "한 주제=한 청크"가 성립
청크 겹침20자 — 제목·표 중심의 구조화 문서라 경계가 단락에 떨어지므로 최소 보호값만 적용. 겹침 과다 시 동일 내용이 검색 상위를 중복 점유하고 로컬 LLM의 한정 컨텍스트를 낭비
질의 방식워크스페이스 query 모드(문서 기반 답변 한정), 인증 키 사용, 타임아웃 30초
장애 처리미가동 시 오류 메시지 반환 후 대화 지속(폴백)

8. 보안 아키텍처

8.1 적용 사항

항목내용
로컬 LLM관제 데이터의 외부 전송 없음. 비용·호출 제한 없음. 폐쇄망 운용 가능
DB 인증Oracle Wallet 기반 mTLS
키 분리공공 API 서비스키는 버전관리 제외 설정 파일로 분리
CORSAPI는 개발 오리진(5173 계열)만 허용
역할 분리USER(승인제)/ADMIN/CIVIL 역할, 승인 전 로그인 차단, 임시 비밀번호 강제 변경 흐름
메일 발송 통제발송 주체 Spring 일원화, AI의 발송은 사용자 명시 요청 시에만 허용(이중 게이트)

9. 확장 시 고려사항

  • 다중 인스턴스 확장 시 인메모리 캐시·WebSocket 브로드캐스트를 Redis(+pub/sub)로 대체한다(캐시 서비스 인터페이스 분리 완료).
  • LLM 처리량 확장은 GPU 서버·vLLM 등 서빙 계층 교체로 대응한다.
  • 수집 확장은 구 단위 샤딩(폴링 분할)으로 대응한다.
