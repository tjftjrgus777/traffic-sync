2. 동작 원리

2.1 ReAct 루프

질문 수신
 → [Thought] 필요한 데이터 판단
 → [Action]  도구 호출 (예: get_district_traffic)
 → [Observation] 결과 관찰
 → (필요 시 반복, 최대 10단계)
 → [Answer]  ① 현재 상태 → ② 혼잡 원인 → ③ 조정 권고  형식으로 답변

전 단계가 SSE 이벤트(action/observation/thought/answer)로 스트리밍되어 화면에 진행 과정이 표시된다.

2.2 멀티에이전트 (주변 분석)

  1. 질문에 주변·근처·인근 표현이 있을 때만 의도 분류 LLM 실행(불필요한 호출 방지). 장소명 추출.
  2. 중심 좌표 반경 0.3km 교차로를 방위각으로 8방향 분류, 방향별 최근접 1개 선정(중심 자신 제외).
  3. 워커 4기가 병렬 분석 — 중심으로 향하는 방향의 진입 속도로 유입 압력 평가.
  4. 순차 토론 3라운드: 속도 공유 → 우선순위 논의 → 합의. 데이터 없는 워커는 제외, 수치 결정 발언 금지.
  5. 오케스트레이터가 코드 계산 권고값(속도 구간별 +18/+10/+4/−5초)과 토론 합의를 결합해 종합 권고.

2.3 시뮬레이션 최적화 (Webster)

Co = (1.5L + 5) / (1 − ΣY)
  L  = 현시 수 × 4초 (주기당 손실시간)
  ΣY = 진입 속도 기반 추정 (u<15: 0.85 / <25: 0.75 / ≤30: 0.65 / >30: 0.50)
안전장치: 현행 주기 ±15% 클램핑 · 심각 등급 주기 하향 금지 · 보행 현시 고정
          · 현시별 변화 최대 ±5초 · 최소 녹색 15초 (반복 적용 시 수렴)

조정 JSON과 메일용 상세 보고서는 코드가 직접 생성하며, LLM은 화면용 설명문만 작성한다.

3. 질의응답 시나리오

S-01. 선택 교차로 상태 질문 — "이 교차로 지금 어때?"
전제지도에서 교차로 선택 상태(ID·이름이 컨텍스트로 주입)
도구 순서get_traffic_data(선택 교차로 ID)
응답 형식① 속도·위험등급·혼잡 요약 ② 혼잡 원인(잔여시간 높은 적색 방향 기준) ③ 현시 조정 권고. 교차로는 이름으로 지칭(숫자 ID 미노출)
S-02. 타 장소 질문 — "잠실역 신호 어때?"
분기 규칙질문에 선택 교차로와 다른 장소명이 있으면 검색 도구를 먼저 호출하도록 프롬프트로 라우팅
도구 순서search_crossroad_by_name("잠실") → get_traffic_data(검색된 ID)
예외검색 결과 없음 시 해당 사실 안내(현 수집 구역 내 교차로만 검색 가능)
S-03. 병목 순위 — "병목 TOP 3 알려줘"
도구 순서get_bottleneck_list → 상위 교차로별 get_traffic_data 상세 조회
응답 형식순위·교차로명·속도·위험등급 표 + 교차로별 원인·권고
S-04. 구 단위 현황 — "강남구 교통 어때?"
도구 순서get_district_traffic(강남구)
응답 형식수집 교차로 수, 평균 속도, 15km/h 이하 병목 목록(속도·위험등급), 날씨, 신호 조정 권고 2~3문장
S-05. 주변 분석(멀티에이전트) — "선릉역 주변 분석해줘"
분기의도 분류 결과 "주변 분석"이면 일반 ReAct 대신 멀티에이전트 흐름으로 재라우팅
화면 표시지도에 중심-워커 연결선·파동, 채팅창에 워커 4기 분석 → 토론 3라운드 → 종합 권고를 실시간 표시
종합 형식① 방향별 현황(평균·방향별 속도) ② 방향별 신호 조정 권고(코드 계산값) ③ 예상 효과 1~2문장
S-06. 시뮬레이션 자동 최적화 — 경로 병목 신호 최적화
트리거시뮬레이션 페이지에서 경로 확정 시 자동 실행(15km/h 미만 구간 존재 시)
입력경로 구간 속도(방향별 포함), 병목 교차로 신호계획(화면 표시본 동봉)
처리Webster 코드 계산 → 조정 JSON 확정 → LLM이 변경 요지 설명문 작성
출력교차로별 "현시N(방향): X초 → Y초" 요약, 슬라이더 자동 반영, 관제사 승인 후 적용. 메일 요청 시 계산 과정 포함 상세 보고서 발송
S-07. 메일 리포트 — "이 분석 결과 이메일로 보내줘"
발송 조건질문에 "이메일/메일" 키워드가 직접 포함된 경우에만 send_email_report 호출 허용(도구 설명·프롬프트 이중 게이트). 수신자는 로그인 사용자 이메일 고정
처리분석 수행 → 리포트 본문 구성(고정 마무리 문구 포함) → Spring 메일 창구로 발송
S-08. 병목 경보 메일 — 구 단위 경보 발송
트리거메인 대시보드 경보 버튼
처리get_district_traffic → 고정 양식 리포트 생성(병목 표·날씨·조치 권고) → Spring이 발송. 병목 없음 시 "상황 양호" 양식
S-09. 음성 명령 — "시뮬레이션으로 가줘" / "강남구 보여줘"
처리STT 텍스트를 의도 분류(JSON 1행: navigate/select_gu/mypage/logout/unknown). 명시적 이동 표현만 인정하고 단순 언급·질문은 unknown 처리
분기해당 의도면 음성 피드백 후 즉시 수행, unknown이면 챗봇(ReAct)으로 폴백
S-10. 도메인 지식 질문 — "비 올 때 신호 어떻게 운영해?"
도구 순서search_project_docs(질의) — AnythingLLM이 프로젝트 문서에서 관련 청크 검색 후 답변 생성
예외RAG 서버 미가동 시 오류 안내만 반환하고 대화는 지속

4. 응답 신뢰성 보강 장치

장치내용
수치 계산의 코드 이관신호 권고값(고정 테이블)·Webster 계산·메일 상세 보고서는 LLM 미사용. 프롬프트에 "계산값 그대로 사용, 임의 변경 금지" 명시
JSON 자동 수리LLM 출력 JSON의 구조 오류를 정규식 5패턴으로 수리 후 파싱(닫는 괄호 보정 포함)
언어 필터중국어(CJK 한자) 혼입 줄 자동 제거 — 모델 특성 방어
형식 강제번호 형식(①②③) 고정, 마크다운 헤더·마무리 인사 금지 등 부정 제약 명시
데이터 격리멀티에이전트 워커는 자기 교차로 데이터만 수신, 무데이터 워커 토론 제외 — 수치 혼동·날조 차단
용어 고정방향 속도 부재를 "측정값 없음"으로 표기(통행 불가로 오해 방지)
생성 중단연결 종료 0.3초 내 감지, 생성 소켓 강제 종료. 정지 API 별도 제공
타임아웃·재시도프론트 120초 타임아웃, 자동 재시도 최대 2회(사용자 정지와 구분)
