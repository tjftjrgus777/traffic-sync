DB 개요

1.1DB 환경 및 접속 정보

항목내용
DB 종류Oracle Autonomous Database (클라우드, Always-Free Tier)
접속 방식Oracle Wallet + JDBC Thin Driver (TNS alias: trafficsync_high)
커넥션 풀HikariCP — 최대 10개, idle timeout 120s, keepalive 60s
ORMSpring Data JPA (Hibernate) — DDL auto: none (수동 관리)
문자셋AL32UTF8 (Unicode)
시간대Oracle DB: UTC / 애플리케이션: Asia/Seoul (LocalDateTime 저장 시 한국 시각)
Flask 직접 접속News_flask_server, flask_server(XGBoost)는 oracledb Python 드라이버로 직접 접속 (같은 Wallet 사용)

2.2관계 유형 상세

부모 테이블자식 테이블관계조인 키DDL 제약비고
CROSSROAD CROSSROAD_SUPPLEMENTAL_MAPPING 1:1 CRSRD_ID 논리적 매핑이 없으면 보조 스케줄러가 생성
SIGNAL_CROSSROAD SIGNAL_PHASE 1:1 INT_NO 논리적 교차로 1개 당 Phase 행 1개 (MAP_NO="0")
SIGNAL_CROSSROAD SIGNAL_PLAN 1:N INT_NO 논리적 시간대별·현시 순서별 여러 행 (PLAN_NO × PLAN_IDX_NO)
COMPLAINTS COMPLAINT_PHOTOS 1:N COMPLAINT_ID 논리적 민원 1건 당 사진 0~N장. 사진 바이트를 BLOB으로 직접 저장.
외래키 제약 미설정 이유: Oracle Autonomous DB Free Tier의 제약 및 JPA auto-DDL none 환경에서 운영 편의성 우선. 애플리케이션 레이어(Spring Boot Service)에서 참조 무결성을 관리한다.
3
테이블 정의서
컬럼 표기 규칙: PK 기본키   FK 외래키(논리)   NN = NOT NULL   - = NULL 허용
USERS
사용자 계정
내부 관제 담당자(USER/ADMIN)와 시민 민원 사용자(CIVIL)를 ROLE 컬럼으로 구분하여 단일 테이블에 관리
PK 타입: VARCHAR · 행 규모: 소규모 · 데이터 출처: 회원가입 / AdminInitializer
키컬럼명Oracle 타입Java 타입NN기본값설명
PKUSER_IDVARCHAR2(50)StringNN-사용자 로그인 아이디 (유니크)
PASSWORDVARCHAR2(100)StringNN-BCrypt 해시 저장. 최소 60자 ($2a$10$...)
NAMEVARCHAR2(50)StringNN-실명
PHONEVARCHAR2(20)String--휴대폰 번호 (아이디 찾기 시 사용)
EMAILVARCHAR2(100)String--이메일 알림·임시비밀번호 발송 대상
ALERT_EMAILNUMBER(1)Integer-01=이메일 알림 수신 동의, 0=거부
ROLEVARCHAR2(10)String-'USER'USER | ADMIN | CIVIL. CIVIL=시민 민원 전용 계정
STATUSVARCHAR2(10)String-'PENDING'PENDING=승인대기 | APPROVED=활성 | REJECTED=거절
CREATED_ATTIMESTAMPLocalDateTime-now()계정 생성 일시 (한국 시각)
IS_TEMP_PWNUMBER(1)Integer-01=임시 비밀번호 발급됨 → 로그인 시 마이페이지 강제 이동
CROSSROAD
V2X 교차로 기본 정보
서울시 V2X 인프라가 설치된 교차로의 ID·이름·위경도. 서버 시작 1회 적재 후 변경 없음.
PK 타입: VARCHAR · 데이터 출처: 국토부 V2X 교차로 정보 API
키컬럼명Oracle 타입Java 타입NN설명
PKCRSRD_IDVARCHAR2StringNN교차로 고유 ID (예: "1007")
CRSRD_NMVARCHAR2String-교차로 이름 (예: "잠실역사거리")
LATNUMBERDouble-위도 (WGS84, 소수점 6자리 이상)
LONNUMBERDouble-경도 (WGS84)
Haversine 반경 조회 JPQL: CrossroadRepository.findWithinRadius(lat, lon, radiusKm) — 구역 선택(fetch-area) 시 반경 내 교차로 목록 추출에 사용.
CROSSROAD_SUPPLEMENTAL_MAPPING
교차로 ↔ 도로링크 매핑
각 교차로에 가장 가까운 TOPIS 속도 링크·위험도 링크를 자동 계산하여 캐시. 24시간마다 재검사.
PK = CROSSROAD.CRSRD_ID (1:1) · 데이터 출처: Spring Boot 자동 계산 (TOPIS 링크 버텍스 파일 기반)
키컬럼명Oracle 타입Java 타입NN설명
PKCRSRD_IDVARCHAR2StringNN교차로 ID (CROSSROAD.CRSRD_ID 참조)
GU_NAMEVARCHAR2String-자치구 이름 (예: "강남구"). 구 필터 조회에 사용.
RISK_SOURCE_LINK_IDVARCHAR2String-위험도 API 호출 시 사용할 도로링크 ID
RISK_LINE_STRINGVARCHAR2(4000)String-위험도 API 호출용 LineString 좌표. 최대 3,900자 제약으로 긴 구간은 분할 처리.
RISK_DISTANCE_METERSNUMBERDouble-교차로 중심 → 위험도 링크 거리 (m)
SPEED_LINK_IDVARCHAR2String-TOPIS 속도 API 호출 시 사용할 링크 ID
SPEED_DISTANCE_METERSNUMBERDouble-교차로 중심 → TOPIS 링크 거리 (m)
UPDATED_AT_MSNUMBERLong-마지막 갱신 epoch ms. 24시간 경과 시 재계산.
CCTV3
UTIC CCTV 메타정보
서울 시내 교통 CCTV의 위치와 UTIC 스트리밍 URL 구성에 필요한 파라미터 저장.
PK 타입: VARCHAR · 데이터 출처: UTIC API 초기 적재 (서버 시작 1회)
키컬럼명Oracle 타입Java 타입NN설명
PKCCTV_IDVARCHAR2StringNNUTIC 발급 CCTV 고유 ID
CCTV_NMVARCHAR2String-CCTV 명칭 (예: "서초IC전방")
LATNUMBERDouble-위도 (카카오맵 마커 표시에 사용)
LONNUMBERDouble-경도
STREAM_IDVARCHAR2String-iframe URL의 id= 파라미터. null 가능 (스트리밍 불가 CCTV)
CCTV_CHNUMBERInteger-iframe URL의 cctvch= 파라미터. null 가능
SIGNAL_CROSSROAD
신호계획 교차로 목록
국토부 getCrossRoadInfoList API로 수집한 지자체 주요도로 교차로 목록. SIGNAL_PHASE·SIGNAL_PLAN의 INT_NO 기준이 된다.
PK 타입: VARCHAR · 데이터 출처: 국토부 신호계획 API (서버 시작 1회)
키컬럼명Oracle 타입Java 타입NN설명
PKINT_NOVARCHAR2StringNN신호계획 교차로 번호 (예: "2904"). CROSSROAD.CRSRD_ID와 다른 체계.
INT_NMVARCHAR2String-교차로 이름
REGION_CDVARCHAR2String-지역 코드 (예: 서울 = "11")
X_COORDVARCHAR2String-경도 × 1e7 문자열. 변환: Integer.parseInt(xCoord) / 1e7
Y_COORDVARCHAR2String-위도 × 1e7 문자열
UPD_DTIMEVARCHAR2String-데이터 갱신 일시 문자열
SIGNAL_PHASE
신호 현시 구성 (A링/B링 방향코드)
각 교차로의 현시 1~8번에 해당하는 방향설정코드. A링과 B링이 같은 현시 번호에서 동시에 녹색이 된다.
복합 PK: (INT_NO, MAP_NO) · 데이터 출처: getCrossRoadInfoDetail
키컬럼명Oracle 타입Java 타입NN설명
PK1INT_NOVARCHAR2StringNN교차로 번호 (SIGNAL_CROSSROAD.INT_NO 참조)
PK2MAP_NOVARCHAR2StringNN맵 번호 (통상 "0"). INT_NO와 합쳐 행 유일성 보장.
INT_NMVARCHAR2String-교차로 이름 (중복 저장, 조회 편의)
REGION_CDVARCHAR2String-지역 코드
A_RING_1 ~ A_RING_8VARCHAR2String-현시 1~8번의 A링 방향코드. 형식: [S/L/P][출발방위각3자리][도착방위각3자리]. 예: "S183003" = 남(183°)→북(003°) 직진
B_RING_1 ~ B_RING_8VARCHAR2String-현시 1~8번의 B링 방향코드. A링과 같은 인덱스끼리 동일 현시에서 동시 녹색 점등.
방향코드 해석: 첫 글자 S=직진(Straight), L=좌회전(Left), P=보행자(Pedestrian). 이후 3자리×2 = 출발/도착 방위각(0°=북, 90°=동, 180°=남, 270°=서). Spring의 parseDirections()가 이를 "북직진", "남좌회전" 등 한글 레이블로 변환.
SIGNAL_PLAN
신호 운영 계획 (현시별 지속시간)
교차로별 시간대별 운영 주기·각 현시 지속시간(초). 시뮬레이션 페이지의 슬라이더 초기값 및 사이클 계산에 사용.
복합 PK: (INT_NO, PLAN_NO, PLAN_IDX_NO) · 데이터 출처: getPlanCROPInfo
키컬럼명Oracle 타입Java 타입NN설명

PK2PLAN_NOVARCHAR2StringNN플랜 번호 (시간대마다 다른 플랜). 예: "1"=오전, "2"=오후

신호계획 3테이블 조합 흐름

시뮬레이션 페이지에서 GET /api/signal/simulation/context/{intNo} 호출 시 다음 순서로 3개 테이블을 조합하여 현시별 방향 + 지속시간 객체를 구성한다.
  1. SIGNAL_PLAN 조회: findByIdIntNo(intNo) → 현재 시각에 해당하는 PLAN_NO의 행들 필터링 (OPER_PLAN_HH/MI 비교)
  2. CYCLE_VAL 추출: 해당 플랜의 전체 사이클 길이(초)
  3. A_RING_1~8 (초): PLAN 행에서 현시별 지속시간 추출
  4. SIGNAL_PHASE 조회: findByIdIntNo(intNo) → A_RING_1~8 (방향코드) 추출
  5. parseDirections(aRingN): 방향코드 → "북직진", "남좌회전" 한글 변환
  6. 결합: phases[n] = { no, sec(Plan.aRing_n), dirs(Phase.aRing_n 파싱) }
  7. 현재 시각 기준 경과 초(elapsed) 계산 → 현재 활성 현시 번호(currentPhaseNo) 및 잔여시간(remainSec) 도출
