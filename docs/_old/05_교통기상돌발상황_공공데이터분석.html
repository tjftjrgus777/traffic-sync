1
분석 개요

1.1 분석 목적 및 범위

TrafficSync는 서울시 전역의 교통 상황을 실시간으로 모니터링하기 위해 국토교통부 V2X 신호 API, 서울시 TOPIS 도로 속도 API, 기상청 초단기실황 API, 공공데이터포털 도로 위험도 API의 4종 공공 데이터를 수집·통합한다. 본 문서는 각 API의 데이터 명세, 수집 방식, 전처리 로직, 활용 방법을 분석하며, AI 에이전트가 교통 상황을 자연어로 해석하기 위해 필요한 교통·기상 도메인 지식을 함께 기술한다.

분석 범위: ① 교통 신호·속도 데이터  |  ② 기상 조건 데이터  |  ③ 도로 위험도(돌발상황 지수) 데이터  |  ④ 데이터 통합 처리 및 품질 관리

TOPIS 링크 버텍스 좌표 변환

서울시 TOPIS 좌표계는 TM(트랜스버스 메르카토르) 기반이며, 카카오맵 지도 및 위험도 API에서 사용하는 WGS84로 변환이 필요하다.

1
버텍스 수집
LinkVertex API 또는 로컬 xlsx 파일에서 링크 ID별 버텍스 순번(seq)과 TM 좌표(tmx, tmy) 수집
2
TM → WGS84 변환
CoordinateTransformService.toWgs84(tmx, tmy) 로 위경도 변환. 한국 중부원점 기준 투영 역변환 적용
3
버텍스 순번 정렬 → TopisLinkGeometry 생성
TreeMap(seq 키)으로 정렬 후 순서대로 GeoPoint 리스트 조립 → TopisLinkGeometry.vertices
4
LineString 조립
RoadRiskApiService.buildLineString(vertices): LineString(lon lat,lon lat,...) 형식. 최대 3900자 제한 (URL 길이 초과 방지)

병목 교차로 필터 기준 (bottleneck_under_15)

AI 에이전트 MCP 도구 get_district_traffic 내부에서 적용하는 이메일 경보 기준이다.

병목 필터 조건
  • 조건: speedKph > 0 AND speedKph ≤ 15 (km/h)
  • 제외: 속도 0 (정차·미수집 구분 불가) 및 null (링크 매핑 없음)

  • 경보 기준: 목록에 교차로 1개 이상 → 관제사 이메일 자동 발송

2.4 신호 최적화 도메인 지식 — Webster 공식

Webster 최적 신호 주기 공식 (교통공학 고전 공식)

Co = (1.5 × L + 5) / (1 − Y)

변수의미단위
Co최적 신호 주기초
L총 손실 시간 (신호 전환 시 미출발 시간, 보통 4초/페이즈)초
Y총 포화도 (각 현시 교통량 / 포화 교통량 합)0~1

계산 예시: L=12초(3페이즈×4초), Y=0.6 → Co = (1.5×12+5) / (1-0.6) = 23 / 0.4 = 57.5초

한계: 정상 상태 가정(피크 시간 부정확), 좌회전·우회전 분리 미반영 → 실시간 데이터 보정 조합 권장

날씨·속도별 권고 신호 주기

조건권고 신호 주기근거
맑음 + 고속 (50km/h↑)30~40초처리량 최대화
맑음 + 저속 (30km/h↓)40~50초대기 행렬 분산
비 + 저속45~60초안전거리 확보, 제동 지연
눈 + 저속60초 이상제동거리 2.5배 증가
출퇴근 피크90~120초긴 주기로 교차로 처리량 ↑
심야60초 이하대기 시간 최소화

신호 최적화 권고 표현 기준

좋은 권고 예시: "비 + 저속(25km/h) 상태로, 현재 60초 주기를 75초로 +15초 연장 권고. 보행자 안전 확보 + 차량 처리량 안정."
나쁜 권고 예시: "신호 늘려야 함."
→ 근거(날씨·속도) + 수치(초) + 효과(보행 안전·처리량)를 함께 제시해야 관제사 신뢰를 얻는다.

5.3 Stale 처리 메커니즘

외부 API 응답 실패 또는 타임아웃 발생 시 직전 캐시값을 유지하면서 해당 데이터의 stale 플래그를 true로 표시한다. 이를 통해 일부 데이터 장애가 발생해도 시스템 전체가 중단되지 않고 가용한 데이터를 계속 서비스한다.

stale 필드설정 조건복구 조건
speedStale TOPIS API 타임아웃(3초) 또는 링크 매핑 없음 다음 60초 주기에 정상 응답 수신 시 false로 초기화
riskStale 위험도 API 타임아웃(3초) 또는 LineString 파라미터 없음 다음 5분 주기에 정상 응답 수신 시 false로 초기화

데이터 활용 시 주요 유의사항

① V2X 신호 잔여시간(rmndCs): 1/10초 단위로 내려온다. 초 변환 시 반드시 ÷10 적용. MCP 서버에서 자동 변환하여 초 단위로 AI에 전달.
② 병목 필터에서 속도 0 제외: speedKph=0은 정차 또는 미수집 구분 불가. 오탐(false positive) 방지를 위해 speed > 0 AND speed ≤ 15 조건을 엄격히 적용.
③ LineString 좌표 순서: WKT 표준은 경도(lon) 먼저, 위도(lat) 나중. String.format("%.7f %.7f", lon, lat) 형식으로 조립. 순서 반전 시 API 오류 또는 엉뚱한 위치 조회.
④ 날씨 데이터 단일 격자 적용: 기상청 5km 격자 기준으로 서울 전역에 동일 날씨 데이터 적용. 강남·강북의 미세 기상 차이나 국지성 소나기 등은 반영되지 않음.

Green Wave (신호 연동) 고려사항

현재 TrafficSync는 교차로 단위 신호 데이터를 수집하며, TOPIS 실시간 도로 소통 정보(상행/하행 속도)와 신호계획 DB를 결합하여 시뮬레이션 페이지에서 병목 구간 신호 최적화를 지원한다. [v1.1 변경 — T Data 미사용]
