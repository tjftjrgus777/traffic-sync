프로젝트 개요

1.1 개발 배경 및 필요성

현대 도시의 교통 관제는 신호 데이터, 도로 속도, 기상 조건, CCTV 영상 등 수십 개의 이질적인 공공 데이터를 동시에 파악해야 하는 복잡한 업무다. 그러나 기존 시스템은 각 데이터 소스를 개별 화면에서만 확인할 수 있어 통합된 실시간 판단이 어렵고, 비전문가가 이해하기 어려운 수치 중심의 인터페이스로 구성되어 있다.

특히 서울시는 V2X(Vehicle-to-Everything) 인프라를 확대하며 실시간 교차로 신호 데이터를 공개하고 있으나, 이를 도로 속도·날씨·위험도 데이터와 결합하여 단일 화면에서 통합 분석하는 플랫폼은 부재한 상황이다. 또한 교통 관계자가 자연어로 교통 현황을 질의하고 AI가 즉각 분석·답변하는 인터페이스 역시 상용 서비스에서 제공되지 않는다.

핵심 문제: 다수 공공 API 데이터가 분산되어 있어 통합 실시간 모니터링 불가 → 교통 이상 탐지 지연 및 신호 최적화 의사결정 비효율

2.2 데이터별 상세 활용 계획

① V2X 신호 데이터 (국토교통부)

교차로 ID별로 8방향(북/동/남/서/북동/남동/남서/북서)의 신호 상태를 30초 주기로 수집한다. 각 방향의 신호 종류(직진·좌회전·보행자·유턴·버스·자전거)와 잔여시간(1/10초 단위 → 초 변환)을 파싱하여 실시간 신호등 시각화에 활용한다. API 타임아웃 발생 시 직전 캐시를 유지하여 데이터 단절 없이 서비스한다.

② 신호계획 데이터 (국토교통부 1320000)

3개 엔드포인트를 통해 교차로 목록, A링/B링 현시별 방향설정코드, 운영 주기 및 각 현시 지속시간을 수집하여 Oracle DB에 영구 저장한다. 신호 시뮬레이션 페이지에서 현재 운영 중인 신호 계획을 기반으로 타이밍 조정 시나리오를 제공한다.

③ TOPIS 도로 속도 (서울시)

서울시 전체 도로 링크(LINK_ID)별 실시간 속도(km/h)와 여행시간을 60초마다 4개 스레드로 병렬 수집한다. TOPIS 링크 버텍스 좌표 파일(topis-link-vertex-2025.xlsx)과 결합하여 교차로 ↔ 도로 링크 매핑 후 속도 기반 혼잡도(원활/서행/혼잡)를 계산한다.

④ 기상청 초단기실황 (기상청)

서울 강남구 기준 격자좌표(KMA Grid 변환)로 10분마다 기온(T1H), 강수량(RN1), 습도(REH), 풍속(WSD)을 수집한다. AI 에이전트가 날씨 현황 질문 시 실시간 기상 데이터를 컨텍스트로 활용하며, 교통 상태 분석 시 악천후 여부를 보조 지표로 포함한다.

⑤ 도로 위험도 (공공데이터포털)

교차로와 매핑된 도로 링크의 LineString 기하 좌표를 API에 전달하여 도로 위험 등급(1~5단계)과 위험 지수(0~100)를 5분마다 수집한다. 4개 스레드 병렬 처리로 수집 시간을 최소화하며, 위험 등급 3 이상 교차로를 사이드바 위험 목록에 우선 표시한다.

⑥ 교통량 조사 이력 데이터 (공공데이터포털)

공공데이터포털(data.go.kr)에서 제공하는 도로구간별 시간대·방향별 교통량 조사 데이터를 모델 학습에 활용한다. 측정 지점(Station_Number), 방향(상행 0 / 하행 1), 위경도, 연·월·요일·시간 등 9개 피처로 XGBoost 회귀 모델을 사전 학습하고 xgboost_traffic_model.joblib으로 저장한다.

추론 시에는 Flask 서버(:5002)가 Oracle DB의 TRAFFIC_STATION 테이블에서 해당 지점의 위경도를 조회하여 오늘 0~23시 × 상행/하행 = 48개 입력 벡터를 생성하고, 저장된 모델로 시간당 교통량(대/시)을 일괄 예측한다. Spring Boot가 프록시하여 프론트엔드 예측 차트에 전달한다.

피처설명
Station_Number교통량 측정 지점 ID
Direction0 = 상행, 1 = 하행
Latitude / Longitude지점 위경도
Hour시간(1~24)
Weekday_Weekend평일=1, 주말=0
Year / Month / Day_of_Week_Num연·월·요일 인덱스

⑦ TOPIS 실시간 도로 소통 정보 — 시뮬레이션 활용 v1.1 변경

서울특별시 TOPIS가 제공하는 실시간 도로 소통 정보(TrafficInfo)에서 도로 링크별 상행·하행 속도(km/h)와 여행시간을 60초 주기로 수집한다. 시뮬레이션 페이지에서는 이 속도 데이터를 국토교통부 신호계획 DB(현시 구성·운영주기)와 교차로 단위로 매핑하여 속도 급락 구간을 병목으로 탐지하고, VWorld 3D 지도 위에 경로와 병목 경유지를 시각화한다.

사용자가 출발지·목적지를 선택하면 경로 상의 병목 교차로를 자동 탐색하고, 해당 교차로의 직진·좌회전 현시 시간을 AI가 분석하여 최적 조정값을 권고한다. 신호 타이밍 조정 전·후 예상 도착시간(제어 전/후 속도 기반)을 비교하여 병목 완화 효과를 정량적으로 제시한다.

3.2 공공데이터 수집·처리·활용 흐름

1
서버 시작 — 정적 데이터 초기 적재
V2X 교차로 정보·신호계획 3종·CCTV 목록·TOPIS 링크 버텍스 파일(xlsx) 을 Oracle DB 및 메모리에 적재. 이미 적재된 경우 스킵.
2
구역 선택 — fetch-area 트리거
사용자가 서울 SVG 지도에서 자치구 선택 → POST /api/fetch-area → DB에서 반경 2.5km 내 교차로 조회 → V2X 신호 일괄 수집 → 보조 데이터(속도·날씨·위험도) 합산 → WebSocket 브로드캐스트.
3
정기 폴링 — 자동 갱신 (스케줄러 4종)
V2X 신호: 30초마다 / TOPIS 속도: 60초마다 (4스레드 병렬) / 도로 위험도: 5분마다 (4스레드 병렬) / 기상청 날씨: 10분마다 / 도로-교차로 매핑: 24시간마다
4
데이터 통합 — TrafficStatus 생성
V2X 신호 데이터에 TOPIS 속도 + 기상청 날씨 + 도로 위험도를 교차로 ID 기준으로 합산. 속도 기반 혼잡도(원활≥40, 서행≥20, 혼잡<20 km/h) 계산 후 단일 TrafficStatus 객체로 통합.
5
실시간 전송 — WebSocket 브로드캐스트
통합된 교차로 상태 Map을 모든 연결된 프론트엔드 세션에 JSON으로 브로드캐스트. 연결 끊김 시 3초 후 자동 재연결.
6
교통량 예측 — XGBoost 추론 (Flask :5002)
사용자가 측정 지점 선택 → GET /api/forecast/station/{stationId} → Spring Boot: Flask :5002에 지점 ID 전달 → Flask: Oracle DB에서 위경도 조회 후 오늘 0~23시 × 상행/하행 48개 입력 벡터 생성 → XGBoost 모델 추론 → 24시간 예측 교통량 반환 → 프론트엔드 꺾은선 차트(상행/하행) 렌더링.
7
AI 분석 — LangGraph ReAct 에이전트
사용자 질문 → Python 에이전트 → MCP 도구(get_traffic_data, get_bottleneck_list 등) 로 Spring API 재호출 → LLM 추론 → SSE 스트리밍으로 사고 과정·답변 실시간 전달.

6.2 수집 데이터 관리

항목관리 방안
개인정보수집 데이터에 개인식별 정보 미포함. 교차로 신호·속도·위험도·날씨는 비개인 공공 데이터.

공공데이터 이용 약관 준수각 API 제공기관의 이용 약관에 따라 데이터를 연구·개발 목적으로만 활용하며 상업적 재배포 금지.
