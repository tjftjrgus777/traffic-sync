AI 에이전트 구조 개요

1.1 LangGraph ReAct 아키텍처

TrafficSync AI 에이전트는 LangGraph의 ReAct(Reason + Act) 패턴을 기반으로 동작한다. LLM이 사용자 질문을 받아 필요한 도구를 결정하고 호출하며, 도구 결과를 관찰해 추가 도구 호출 또는 최종 응답을 생성하는 루프를 반복한다.

계층기술역할
사용자 인터페이스React 챗봇 패널질문 입력, SSE 스트리밍 응답 표시
Spring BootChatController (포트 8080)요청 수신, Python 에이전트로 프록시
AI 에이전트FastAPI + LangGraph (포트 8001)ReAct 루프, 도구 선택·호출 관리
MCP 도구 서버mcp_server.py (stdio)Spring REST API 호출, 데이터 가공
LLMOllama qwen3:30b-a3b (포트 11434)추론 엔진, thinking 모드 지원
ReAct 루프 단계:
① Observe — 사용자 질문 + 이전 도구 결과 관찰
② Think — LLM이 다음 행동 결정 (도구 호출 vs 최종 응답, <think> 블록으로 노출)
③ Act — MCP 도구 호출 실행
→ 도구 결과를 다시 ① Observe → 평균 1~3회 반복 후 최종 응답 생성

1.2 MCP 도구 목록 (9종)

#도구명파라미터호출 API주요 용도
1 get_traffic_data crossroad_id GET /api/context/{id} 특정 교차로 실시간 신호·속도·날씨·위험도 전체 조회
2 get_bottleneck_list 없음 GET /api/signals 캐시 전체에서 속도 낮은 교차로 TOP 10 (속도 0 제외)
3 search_crossroad_by_name name GET /api/signals (필터) 교차로 이름 부분 일치 검색 → crsrdId 획득
4 get_district_traffic district_name GET /api/signals (집계) 자치구 집계 — 교차로 수, 15km/h 이하 병목 목록, 날씨
5 set_signal_timing crossroad_id, delay POST /api/signal/adjust 신호 타이밍 조정 요청 (현재 미구현, Human-in-the-loop)
6 send_alert message 콘솔 로그 관제사 알림 (향후 Slack·이메일 확장)
7 send_email_report subject, body, to? Gmail SMTP SSL 465 이메일 발송. to 무시, 로그인 유저 이메일로만 전송
8 get_simulation_context int_no GET /api/signal/simulation/context/{intNo} 신호 시뮬레이션 교차로 계획 조회 (현시·주기·방향)
9 search_project_docs query AnythingLLM RAG 도메인 지식 검색 — Webster 공식, 날씨 영향, 병목 기준
