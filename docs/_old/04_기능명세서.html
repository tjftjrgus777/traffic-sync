1. 문서 목적 및 기능 분류 개요

본 문서는 TrafficSync 시스템의 각 기능에 대해 행위자, 사전 조건, 처리 흐름, 입출력, 예외 처리를 상세히 기술한다. 개발·테스트·발표 검토 시 기능의 동작 기준으로 활용한다.

2. FR-AUTH — 사용자 인증 및 계정 관리
FR-AUTH-001 로그인 행위자: 사용자(일반/관리자)
설명이메일·비밀번호를 입력해 JWT 토큰을 발급받고 시스템에 접근한다.
사전 조건회원가입이 완료되어 있고 관리자 승인 상태여야 한다.
주요 흐름
  • 1이메일·비밀번호 입력 후 로그인 버튼 클릭
  • 2POST /api/auth/login { email, password } 요청
  • 3Spring Boot: USERS 테이블에서 email로 사용자 조회 → BCrypt 패스워드 검증
  • 4검증 성공 시 JWT 토큰(유효기간 7일) 생성 후 응답
  • 5프론트엔드: localStorage["ts_user"] = { token, email, name, role } 저장
  • 6role에 따라 일반 사용자는 MainDashboard, 관리자는 관리 화면으로 이동
예외 처리
이메일 없음 → "이메일 또는 비밀번호가 올바르지 않습니다" 비밀번호 불일치 → 동일 메시지 (보안상 구분하지 않음) 미승인 계정 → "관리자 승인 대기 중입니다"
관련
POST /api/auth/login LoginPage.jsx UserController.java
FR-AUTH-002 회원가입 행위자: 신규 사용자
설명이름·이메일·비밀번호를 입력해 계정을 생성한다. 관리자 승인 후 로그인 가능.
주요 흐름
  • 1이름·이메일·비밀번호·비밀번호 확인 입력
  • 2POST /api/auth/register { name, email, password } 요청
  • 3이메일 중복 확인 → BCrypt 해시 후 USERS 테이블에 INSERT (role=PENDING)
  • 4"가입 완료, 관리자 승인 대기 중" 메시지 표시 후 로그인 화면으로 이동
예외 처리
이메일 중복 → "이미 사용 중인 이메일입니다" 비밀번호 불일치 → "비밀번호가 일치하지 않습니다"
관련
POST /api/auth/register LoginPage.jsx
FR-AUTH-003 아이디(이메일) 찾기 행위자: 사용자
설명가입 시 입력한 이름으로 등록된 이메일을 조회한다.
주요 흐름
  • 1이름 입력 후 찾기 클릭
  • 2GET /api/auth/find-id?name={name} 요청
  • 3USERS 테이블에서 name으로 이메일 조회 → 일부 마스킹 처리 후 표시
관련
GET /api/auth/find-idLoginPage.jsx
FR-AUTH-004 임시 비밀번호 발급 (비밀번호 찾기) 행위자: 사용자
설명이름과 이메일이 일치하면 임시 비밀번호를 생성해 해당 이메일로 발송한다.
주요 흐름
  • 1이름·이메일 입력 후 발송 클릭
  • 2POST /api/auth/find-pw { name, email } 요청
  • 3이름·이메일 일치 확인 → 임시 비밀번호 생성 → BCrypt 해시 후 DB 갱신
  • 4Naver SMTP로 임시 비밀번호 이메일 발송
  • 5"임시 비밀번호를 이메일로 발송했습니다" 안내
관련
POST /api/auth/find-pwEmailService.java
FR-AUTH-005 비밀번호 변경 행위자: 로그인된 사용자
설명현재 비밀번호를 확인한 후 새 비밀번호로 변경한다.
주요 흐름
  • 1현재 비밀번호·새 비밀번호·새 비밀번호 확인 입력
  • 2POST /api/auth/change-pw — Authorization 헤더에 JWT 포함
  • 3현재 비밀번호 BCrypt 검증 → 새 비밀번호 해시 후 DB 갱신
관련
POST /api/auth/change-pwMyPage.jsx
FR-AUTH-006 관리자 사용자 승인 / 거절 행위자: 관리자(ADMIN)
설명대기 중인 신규 가입자를 관리자가 승인하거나 거절한다.
주요 흐름
  • 1GET /api/auth/admin/users — PENDING 상태 사용자 목록 조회
  • 2승인: POST /api/auth/admin/approve/{userId} → role=ACTIVE 변경
  • 3거절: POST /api/auth/admin/reject/{userId} → 계정 삭제 또는 role=REJECTED
관련
GET /api/auth/admin/users POST /api/auth/admin/approve/{userId} POST /api/auth/admin/reject/{userId}
3. FR-DASH — 메인 대시보드
FR-DASH-001 구별 교통 현황 카드 표시 행위자: 시스템 (WebSocket 수신)
설명서울 25개 구별 교통 현황(평균 속도, 혼잡도, 위험 교차로 수)을 카드 형태로 표시한다. WebSocket으로 수신된 wsData를 구별로 집계한다.
주요 흐름
  • 1App.jsx에서 WebSocket(ws://localhost:8080/ws/traffic) 연결 유지
  • 210초마다 TrafficStatus[] JSON 수신 → wsData 상태 갱신
  • 3wsData를 구이름(guName)으로 그룹화 → 구별 평균 속도·혼잡 교차로 수 계산
  • 4SeoulSvgMap(서울 지도 SVG)에 구별 색상 오버레이 렌더링
  • 5우측 GU_LIST 카드에 구별 속도 · 위험도 점수 표시
출력
구별 평균 속도 (km/h) 위험 교차로 수 혼잡 상태 색상 오버레이
관련
MainDashboard.jsxSeoulSvgMap.jsxSpeedChart.jsxWaitChart.jsx
FR-DASH-002 구 선택 및 지도 화면 전환 행위자: 사용자
설명구 카드 또는 SVG 지도에서 특정 구를 클릭하면 해당 구의 교차로 데이터를 수집하고 실시간 지도 화면으로 전환한다.
주요 흐름
  • 1구 카드 클릭
  • 2POST /api/fetch-area { guName } 요청 → 서버: 해당 구 교차로 전체 데이터 수집 시작 (시나리오 A)
  • 3서버: 중심 좌표를 해당 구 중심으로 업데이트, V2X·TOPIS·위험도 수집 → WebSocket 브로드캐스트
  • 4프론트: MapDashboard로 라우팅 (initialCenter = 해당 구 중심 좌표)
관련
POST /api/fetch-areaMainDashboard.jsxMapController.java
FR-DASH-003 병목 이메일 리포트 발송 행위자: 사용자
설명구 카드의 "병목 메일" 버튼을 클릭하면 AI 에이전트가 해당 구의 병목 현황을 분석하여 로그인 이메일로 HTML 리포트를 발송한다. 처리 중 ReAct 추론 과정을 토스트로 표시한다.
주요 흐름

  • 3AI 에이전트: MCP get_district_traffic 도구로 병목 교차로 조회 → send_email_report 도구로 HTML 리포트 이메일 발송
  • 4ReActToast: thought/action/observation 단계를 실시간으로 토스트 팝업에 표시
  • 5발송 완료 시 버튼 "✓ 메일 전송됨"으로 변경 (3초 후 원복)

4. FR-MAP — 실시간 교차로 지도
FR-MAP-001 교차로 마커 실시간 표시 행위자: 시스템 (WebSocket 수신)
설명카카오맵 위에 교차로 위치에 마커를 표시하고, 신호 상태(색상)·혼잡도·위험도에 따라 마커 색상을 10초마다 자동 갱신한다.
주요 흐름
  • 1WebSocket에서 TrafficStatus[] 수신 → wsData 갱신
  • 2KakaoMapView: wsData 변경 시 기존 마커 제거 후 재생성
  • 3마커 색상 결정 기준:
    · 현재 신호 Green → 초록 / Red → 빨강 / Yellow → 노랑
    · 위험도 높음(riskGrade ≥ 3) → 주황 테두리 추가
    · 혼잡(congestion="혼잡") → 마커 크기 확대
  • 4CCTV 카메라 위치도 별도 아이콘(📷)으로 오버레이
관련
KakaoMapView.jsxMapDashboard.jsx

주요 흐름

  • 4WebSocket 갱신 시 selected 교차로 데이터 자동 업데이트 (10초 주기)
관련
